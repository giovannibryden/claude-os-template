# Contributing to Claude OS

Thanks for considering improvements to the Claude OS template!

## How to Contribute

### Reporting Issues

If you find a problem with the template:
1. Check if it's already reported in Issues
2. If not, open a new issue with:
   - Clear description of the problem
   - Steps to reproduce (if applicable)
   - What you expected vs. what happened
   - Your setup (OS, Claude version, etc.)

### Suggesting Enhancements

Have an idea for improving the template?
1. Open an issue labeled "enhancement"
2. Describe the use case and why it would be valuable
3. Provide examples if possible
4. Consider whether it's broadly applicable or specific to your workflow

### Sharing Workflows

Developed a useful pattern? Share it:
1. Document it clearly in markdown
2. Open a PR adding it to WORKFLOWS.md
3. Include:
   - What problem it solves
   - When to use it
   - Step-by-step instructions
   - Example output
4. Make sure it's general enough for other managers to use

### Improving Documentation

Found something unclear?
1. Open a PR with your improved version
2. Keep the tone direct and practical
3. Use real examples where possible
4. Test instructions before submitting

### Adding Templates

Have a communication template others would find useful?
1. Add it to `communications/templates/`
2. Follow the existing format:
   - Clear header explaining when to use it
   - Template with [brackets] for variables
   - Variable list at the bottom
   - Tips section
3. Make it generic (no company-specific terms)

## Pull Request Process

1. Fork the repo
2. Create a branch for your changes
3. Make your changes
4. Test them in your own Claude OS instance
5. Submit a PR with:
   - Clear description of what changed
   - Why it's valuable
   - Any testing you did

## What We're Looking For

**Good contributions:**
- Solve real problems managers face
- Work across different team types and industries
- Are well-documented and tested
- Maintain the system's philosophy (simple, practical, focused)

**Less ideal contributions:**
- Too specific to one industry or role
- Add complexity without clear value
- Require external dependencies
- Duplicate existing functionality

## Design Philosophy

Keep these principles in mind:

1. **Simple over clever** - If it requires explanation, simplify it
2. **Practical over comprehensive** - Better to do one thing well than many things poorly
3. **Opinionated over configurable** - Provide a good default, not infinite options
4. **Action-oriented** - Help people do things, not just organize information
5. **Low friction** - Reduce barriers to capturing information

## Questions?

Not sure if your idea fits? Open an issue and ask! We're happy to discuss before you invest time in a PR.

## Code of Conduct

- Be respectful and constructive
- Focus on the idea, not the person
- Assume good intent
- Help newcomers
- Keep discussions on-topic
